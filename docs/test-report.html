网站：yipiao-collab-pengcheng.tartfig256.chatgpt.site ｜ 试跑时间：2026-11-12 18:14–18:19 ｜ 目标：彻底新开一单（安特卫普 → 上海，100 套桌椅），分五方角色走完整流程

结论

新开一单未走通：被登录墙挡住。全站唯一的新建入口「新建货单」可以打开并填写表单，但提交后只提示「请登录后操作」，不生成货单；登录跳转的是外部 OpenAI 账号页（auth.openai.com）。「云端货单」「邀请码加入」同样要求先登录。因此新单没有进入预检、待办、状态推进等后续环节。

未登录可用的部分是一个演示工作台（模拟货单），五方角色、资料版本、协同待办、沟通、操作记录均可实际操作。下文的任务流程详解即基于该演示台逐页、逐角色实测；凡涉及新单之处均单独标注。

  2. 表单字段（均已按本单填写）：货单名称「桌椅出口 · 安特卫普-上海」；起运地「安特卫普 · Antwerp」；目的地「上海 · Shanghai」；货物名称「桌椅 / Tables and chairs」；货物数量「100 套」；计划出运日期 2026-11-20（日期框不能直接输入，需点开后逐字键入）。
  3. 提交结果：点击「建立云端协同空间」→ 按钮短暂显示「正在建立…」→ 页面提示「请登录后操作」，弹窗不关闭，背后仍是演示单（当前货单仍为「01票」）。
  4. 登录去向：弹窗内「登录账号」跳转 auth.openai.com（OpenAI 账号：邮箱/Google/Apple/Microsoft/手机号）。本次试跑未登录任何外部账号。
  5. 其他路径：左侧「云端货单」点开只提示「请先登录后使用云端协同」；「邀请码加入」用本站生成的演示码提交，同样被「请登录后操作」挡住。

继续推进的唯一方式：由账号持有人本人登录后，再重新走新建流程。

二、任务流程详细介绍（演示工作台实测）

平台把一票业务分成四个阶段，顶部进度条常显：

阶段 1 建立货单 → 阶段 2 资料协同 → 阶段 3 运输反馈 → 阶段 4 交付确认
演示单停留在阶段 2；附注：「当前显示协同阶段；实际运输进度以承运方反馈为准。」

环节 1 · 建立货单与邀请成员

  • 货单由任一参与方建立（需登录），生成协同空间；货单要素：名称、起运地、目的地、货物名称、货物数量、计划出运日期。
  • 其余四方通过「邀请成员」生成的邀请码加入本票，并选定各自角色（卖家 / 货代 / 船公司 / 地方物流 / 买家）。
  • 演示台的成员为：卖家「森屿家居」、货代「远航国际物流」、船公司「Ocean Link」、地方物流「港联运输」、买家「Nord Living」，每人标注权限（如买家：查看、留言、确认）。

环节 2 · 资料与版本（平台核心）

  • 文件列表：本票文件集中存放（演示单为 1 份「装箱资料」示例文件），支持查看、下载；「上传文件」按钮在演示台点击无可见反应。
  • 版本机制：卖家「更新资料」修改货物名称/数量后生成新版本（如 V2、V3），旧版本进入「版本存档」时间线，变更点被明确标出——演示单的差异为「装箱件数：100 → 120 箱（1 项变更）」。
  • 确认机制：当前版本须由卖家确认，弹窗写明「确认后，该版本将作为各方核对的唯一依据。」确认后状态由「Vx 待确认」变为「Vx 已确认」，顶部状态栏同步显示「资料版本：Vx 已确认 / 卖家已确认当前货物资料」。
  • 规则提示（原文）：「货物名称或数量修改后，平台保留旧记录，并重新请求卖家确认。」
  • 注意：演示台没有独立的「预检报告 / 差异清单」页，也没有比对提单、发票、装箱单的自动校验；所谓差异处理目前就是版本变更标记 + 卖家确认这一步。

环节 3 · 五方协同待办（每方一件事）

待办页标题「五方协同待办」，规则（原文）：「当前以『X』身份处理事项；其他角色的任务可查看，不可代办。」实测非本人角色的操作按钮为禁用态。每项待办含：事项、负责角色、状态（待处理 / 已完成）、「切换完成状态」复选框。

角色待办事项操作区与字段完成方式（实测）
卖家确认装箱件数变更（100 → 120 箱）「确认 Vx」弹窗：货物名称、货物数量，按钮「确认 Vx 资料准确」确认后弹「已记录当前版本确认」；待办仍显示待处理，需再手动勾选复选框才算完成
货代复核运输指示并完成提交说明文案：「由卖家确认，货代复核后沿原渠道提交。」无额外表单卖家未确认新版本时也能直接勾选完成，无前置顺序校验
船公司提供承运反馈：订舱确认与单证办理状态承运反馈：订舱编号、船名航次、单证办理状态、备注填入后「保存并同步至协同」，总览页即时显示；待办仍需手动勾选
地方物流确认提货时间并同步交接信息提货与交接安排：提货时间、提货联系人、提货地点、交接说明同上，保存后总览同步显示
买家确认收货资料与交付要求收货与交付要求：收货单位、收货地址、交付时间要求、备注同上，保存后总览同步显示

环节 4 · 沟通与留痕

  • 沟通记录：本票留言流，五方共用，可搜本票资料；留言即时上墙并标注角色与时间（实测以货代身份发送成功）。
  • 操作记录：时间线自动记录每一次动作（确认、完成待办、发送留言、生成邀请码等），支持「导出操作记录」——实测点击只弹「协同记录已导出」，未实际下载到文件。
  • 角色切换：顶部「切换角色」可在五方之间切换查看各自工作台；但弹窗明确提示切换将重置模拟货单，实测切换后先前留言消失，演示修改不跨角色保留。

环节 5 · 运输反馈与交付确认（阶段 3、4）

  • 船公司、地方物流、买家三方反馈保存后，总览页对应区块会显示内容；但进度条不自动推进，实测三方都填完仍停在「2 资料协同」。
  • 未见到企划书里「待确认 / 已提交 / 处理中 / 待补充 / 已完成」这套状态流转在运输环节的实际呈现。

环节 6 · 服务购买

全站未找到。左侧导航与工作台页签中没有服务、购买、套餐、价格任何入口，总览页内搜索「服务 / 购买 / 价格」无结果，无金额与下单按钮。企划书初赛原型规划的第四页「服务购买」尚未实现。

四、发现的问题（按重要程度）

  1. 新建货单被登录墙阻断（见第一节），且登录绑定 OpenAI 账号——评委若自行试用也会卡在同一处，演示前务必预演。
  2. 确认与待办不联动、无顺序校验：卖家确认版本后待办仍是待处理；货代可在卖家确认前就把复核标完成。这与企划书「状态以确认记录为准」的卖点直接冲突，是流程逻辑上最该先修的一处。
  3. 阶段不自动推进：三方反馈齐了仍停在阶段 2，阶段 3、4 形同摆设。
  4. 邀请码格式自相矛盾：加入弹窗要求「粘贴完整的 32 位邀请码」，本站生成的演示码却是「DEMO-卖家-IQ1KFATK」格式。
  5. 计数不一致：沟通记录新增留言后标题计数不更新；待办完成数与左侧徽标数字对不上（出现过完成数 2/5 不变、徽标 4→3 的情况）。
  6. 导出无文件：「导出操作记录 / 导出协同记录」只弹提示，不产生下载。
  7. 「上传文件」无反应：点击后没有上传面板或文件选择。
  8. 版本存档重复：V2 在时间线里出现两次。
  9. 切换角色重置演示数据：跨角色演示时修改互相丢失（直接改网址 ?role= 参数时行为又不一致）。
  10. 演示单标题与内容矛盾（试跑编辑所致）：标题仍是「实木餐椅出口 · 鹿特丹」，内容一度被改成桌椅/100 套——正式演示前建议重置演示数据。
  11. 日期输入难用：新建表单日期框不能直接键入，需点开逐字输入。

本轮新确认的问题

  1. 待办本质上是纯手动勾选的圆圈：实质操作不驱动待办，待办完成也不校验任何条件，还可反复勾回待处理——全站没有状态机。
  2. 留痕同样随切换清零：操作记录只剩当前角色会话内的条目，跨角色无留痕，与「每一份确认都有依据」的卖点冲突。
  3. 版本存档逻辑颠倒：只在有新版本后才出现，存的却是旧版本的两张重复卡，最新版本反而不入档。
