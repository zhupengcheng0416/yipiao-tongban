一票通办原型网站 · 完整优化建议

依据：2026-11-12 两轮实测（首轮逐页逐角色走查；次轮针对 11 个问题回归，新单仍被登录墙阻断、仅修复 2 条，另发现新问题 6 个）｜ 目标：初赛现场可完整演示企划书的四页原型与五方协同流程

总原则

这个原型的任务不是做成产品，而是在评委面前 5 分钟讲完企划书的故事：发现问题 → 确认 → 提交 → 核实完成，并且让「服务购买」页把商业模式落到屏幕上。所有优化按一个标准排序：是否影响现场演示走通、是否与企划书卖点冲突。与卖点直接冲突的逻辑问题（确认不算数、顺序可乱序、阶段不动）优先级高于任何视觉细节。

P0 · 阻断级：演示走不通的问题

1. 登录墙：演示模式必须能独立开单

  • 现状：新建货单、云端货单、邀请码加入全部要求登录，登录绑定外部 OpenAI 账号。评委自行试用、答辩现场换设备、网络不可控时都会卡死。
  • 建议（任选其一，推荐第一种）：
    ① 增加「演示模式本地开单」：未登录时新建货单在本机创建一张本地货单（明确标注"本地演示"），全流程可走，登录只影响云端保存与跨设备协同；
    ② 若必须保留登录：提前准备一个专用演示账号，登录态写死在演示链接里（带 token 的直达链接），并准备离线录屏兜底。
  • 验收：全新浏览器、无登录状态下，从「新建货单」填表提交，能生成货单号并进入该单工作台。

2. 修复新建表单污染演示单（数据绑定错误）

  • 现状：在新建弹窗输入货物名称、数量、出运日期，会实时写进当前演示单（关闭弹窗、刷新仍在），但货单名称、起运地、目的地又不写入——同一表单一半字段双向绑定、一半没有。
  • 建议：新建表单使用独立的表单状态，与当前货单数据完全隔离；只有提交成功才创建新单并切换过去；取消/关闭弹窗不产生任何数据变化。
  • 验收：打开新建弹窗任意填写后直接关闭，当前货单所有字段与打开前逐项一致。

3. 状态机与联动：确认必须算数，顺序必须成立

这是企划书的核心卖点（"提交状态与完成状态分开""状态以责任方确认为准"），目前实现与卖点相反，是全站最该先修的一组：

规则建议实现验收
确认 → 待办自动完成卖家点「确认 Vx 资料准确」后，对应的"确认资料"待办自动变已完成，不再需要手动勾复选框；各方「保存并同步」反馈同理，保存成功即完成对应待办确认后回到待办页，该项已完成，全程未点复选框
新版本 → 旧待办失效资料产生新版本（如 V4）后，基于旧版本的确认待办自动回到待处理，并生成/刷新"确认新版本"待办；旧确认保留在操作记录里，不算作对新版本的确认卖家已确认 V3 后，货代改资料生成 V4，卖家待办重新亮起"确认 V4"
顺序校验后置待办在前置未完成时锁定：货代「复核运输指示」在卖家确认当前版本前不可勾选，点锁定项时给出明确提示（如"等待卖家确认 V4 后可复核"），而不是静默禁用版本待确认时尝试完成货代待办，被拦截且看到原因文案
阶段自动推进定义每阶段的进入条件并自动切换：阶段2→3：当前版本已确认且货代复核完成；阶段3→4：船公司承运反馈已保存；阶段4 完成：买家确认收货要求且地方物流交接信息齐备（具体口径按演示脚本定死即可）按顺序走完五方操作，进度条从 2 走到 3 再到 4
待办状态与内容一致待办完成必须以对应内容已填写/已确认为准；地方物流待办目前默认"已完成"但提货四项全是"等待填写"，二者必须统一（改为待处理，或预填内容）任一待办显示已完成时，其操作区内容均非空

4. 切换角色不重置数据

  • 现状：每次切换角色，演示货单回滚到初始态——五方协同恰恰要演示"甲做的事乙看得见"，现在无法在一次连续操作中累积，演示时只能靠嘴解释。
  • 建议：演示数据改为一份共享状态，五方共用、切换保留；另设一个显式「重置演示数据」按钮放在不显眼处，需要重演时手动点。网址参数 ?role= 填无效值时回退到默认角色并给出提示，地址栏与实际角色保持一致。
  • 验收：卖家确认版本 → 切到货代，确认结果仍在；五方依次操作后切回卖家，全部成果保留。

P1 · 功能补齐：对齐企划书四页原型

5. 补「服务购买」页（企划书第四页，目前全站无入口）

  • 内容直接取企划书：基础服务包——一票档案 + 一次预检 + 一次修改后复核 + 最多三次主动跟进，跟进期五个工作日，测试价 200 元/票（页面标注"试点测试价"）；复杂事项单独报价的说明；超出次数的超额报价入口。
  • 最小实现：一个展示页 + 「购买本票服务」按钮 → 选包 → 生成一条服务订单记录，状态回到该票的服务栏（如"已购基础包 · 跟进 1/3 次"）。不需要真支付，走通"选—订—状态可见"即可。
  • 作用：商业模式 25% 的可行性分，一半要靠这页把"谁付钱、买什么、多少钱"落到屏幕上。

6. 把「单证预检」做成最小可用，而不是只有版本标记

  • 现状：全站搜不到"预检""差异"；只有「核对字段」两行（货物名称、数量）和版本变更标记。这是企划书的第一卖点（创新性 25%），现在等于没有演示载体。
  • 最小实现（规则写死即可，不必真做 OCR）：对演示资料跑一组固定规则，输出差异清单页：
    ① 必填项检查：收货人地址、付款人信息、联系人等缺项标红并指出缺在哪份文件；
    ② 跨文件比对：装箱单 vs 提单草稿 vs 订舱资料的货物名称、件数、重量逐项对照，不一致的行并排展示两处原文；
    ③ 版本差异：新旧版本字段级 diff（现在的"件数 100→120"就是雏形，扩展到全部关键字段）。
    每条差异给三个动作：确认修改 / 忽略并注明原因 / 发起待办给责任方——正好接上协同待办。
  • 演示案例建议：把企划书里的椅子案例做进预检：海外客户更新了收货人地址、旧装运指示未同步——预检抓出"提单草稿收货人地址 ≠ 最新装运指示"，并提示按达飞指南修改提单涉及费用与保函，让评委一眼看到"预检省的是真金白银"。

7. 上传文件真正可用

  • 现状：「上传文件」点击无任何反应。建议：至少能选文件、进列表、生成新版本并进入待确认流程；文件内容解析不了没关系，演示要的是"上传—成版本—被预检—被确认"这条链。
  • 验收：上传任意 PDF/图片后，文件列表出现该文件，版本存档多一条记录。

P1 · 数据与一致性修复

问题建议
版本存档 V2 重复出现两次存档按"一次动作一条"生成：上传、更新、确认是三种动作可以分列，但同一版本同一动作不得重复；每条标注动作类型与操作者
初始态版本存档区块不显示区块常显；只有一条记录时显示一条，不要整块隐藏，避免评委以为功能不存在
邀请码格式矛盾统一口径：要么加入框接受演示码格式并写明位数，要么生成码改为与提示一致的格式；演示码与正式码的区分标注保留现在的写法即可
「云端货单」点击只有一句飘字给一个正经弹窗：说明需登录、登录后能做什么、一个「去登录」按钮；不要只在页面底部闪一行字
日期输入难用换成可整段输入的日期控件（或文本框+格式校验），至少支持粘贴 2026-11-20 这种完整字符串
计数类问题（已修复）保持现状；后续任何新列表都遵守"标题计数=实际条数、徽标=未完成数"同一口径
导出（已修复，能下载文件）锦上添花：导出文件名带货单号与日期，内容包含操作记录全文，答辩时可当"确认留痕"的证据展示

P2 · 演示体验与呈现

  1. 演示数据换成比赛案例本身：现在演示单是"实木餐椅 · 上海→鹿特丹"，与企划书的椅子案例、试跑的安特卫普→上海 100 套桌椅都不是同一票。建议演示单就固定为一票完整故事：货物、路线、参与方、差异点都与讲稿一致，评委打开页面看到的就是正在讲的那一单。标题、编号、内容三者必须自洽（目前出现过标题是餐椅、内容是桌椅的矛盾，就是表单污染 bug 所致，修 P0-2 后再统一数据）。
  2. 五方视角差异再拉开一点：现在各角色操作区结构雷同（都是填四项保存）。建议每个角色页顶部放一句"我在本票的职责"，关键动作按钮用角色语言命名（船公司"提交承运反馈"、买家"确认收货要求"已部分做到），评委扫一眼就懂分工。
  3. 状态用词与企划书统一：企划书定义的状态是「待确认 / 已提交 / 处理中 / 待补充 / 已完成」，页面目前只有待处理/已完成两档。在待办和承运反馈里把这套状态真正用起来，"提交了≠办完了"这个核心观点才看得见。
  4. 留痕可视化：操作记录是加分项，答辩时会讲"每一份确认都有依据"。建议操作记录支持按版本/按人筛选，并把"谁、何时、确认了哪一版"做成可截图的一屏。
  5. 空状态与失败提示规范化：所有按钮点击必须有可见反馈（成功、失败、为什么失败、下一步做什么），杜绝"点了没反应"（上传、云端货单两处已中招）。
  6. 移动端扫一眼：评委可能用手机打开链接，至少保证总览页和待办页在手机宽度下不横滚、按钮可点。

建议的演示动线（修好 P0 后 5 分钟可走完）

新建货单（安特卫普→上海，100 套桌椅）→ 邀请四方加入 → 卖家上传资料 → 预检跑出差异清单（收货人地址不一致 + 一项缺项）→ 卖家确认新版本（待办自动完成）→ 货代复核提交（此时才解锁）→ 船公司回填承运反馈（阶段推进到运输反馈）→ 地方物流填提货安排、买家确认收货要求（阶段到交付确认）→ 打开服务购买页：基础包 200 元/票，本票跟进次数与状态一目了然 → 收尾展示操作记录：全程谁确认了什么，一屏留痕。

这条动线与企划书模拟案例的六步（建立档案→发现差异→客户确认→安排办理→跟进完成→结算复盘）一一对应，讲稿不用另写。

修复顺序建议

  1. 第一批（不做完不能演示）：P0-1 演示开单、P0-2 表单污染、P0-3 状态联动四条规则、P0-4 切换不重置。
  2. 第二批（决定分数上限）：P1-5 服务购买页、P1-6 预检差异清单、P1-7 上传可用。
  3. 第三批（有余力再清）：P1 一致性五条、P2 呈现六条。

说明：本建议基于两轮实测结果与企划书文本，未涉及网站代码实现方式；每条均给出可复测的验收点，下一轮试跑可按验收列逐项回归。
