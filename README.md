# 一票通办 · 货代单证协同演示（新版）

达飞杯初赛作品「一票通办」的交互原型（新版）：以**货代操作员处理一票单证**为主线，评委看到的是——导入资料 → 系统比对标出问题 → 客户只确认有争议的内容 → 生成可继续办理的草稿 → 提交后用回件核对收尾。

在线演示：https://zhupengcheng0416.github.io/yipiao-tongban/

英文版（供外籍评委，流程与中文版完全一致，两版右上角可互相切换）：https://zhupengcheng0416.github.io/yipiao-tongban/index-en.html

## 两个入口（角色切换保留，一人可演示双方）

- **货代工作台**：建单、导入资料、运行预检、复核差异、发送确认请求、导出草稿、核对回件。
- **出口企业确认页**：只看待确认事项及原文，逐项补充/确认，确认绑定具体版本。
- 船公司反馈并入「草稿与回件」的提交与回件模块（模拟回件）；买家、地方物流列为后续扩展，不参与首阶段完成判定。
- 邀请码进入指定货单的确认页；当前为本地演示，不支持跨设备真实协作。

## 五个页面（沿操作顺序）

1. **一票总览**：货单信息、资料截止、当前版本、资料处理进度、阻塞问题与下一步。
2. **资料与预检**：三份独立示例资料（装箱单/商业发票/装运指示草稿）逐字段真实比对；不一致 / 一致 / 未参与检查 / 识别不确定分别显示。数据变，结果跟着变。
3. **客户确认**：争议项由预检差异自动生成；客户逐项确认并留依据，记录谁、何时、确认了哪些字段、对应哪个版本。
4. **草稿与回件**：按确认后字段生成装运指示草稿并下载 Excel（内容与页面一致）；记录提交后进入等待回件，回件保留旧地址会被核对标出，修正回件核对通过才算本票资料流程完成。
5. **套餐与用量**：企划书测试方案 600 元/月含 50 票（价格假设）；同票重检、重导出不重复扣票，额外人工复核另行报价。

## 状态规则

- 关键差异未解决，不能生成草稿、不能进入可提交状态。
- 确认绑定具体版本；相关字段被修改后，对应确认自动失效，需重新确认。
- 已提交资料再修改：原提交记录保留，新增修改事项。
- 勾选/留言不能代替修改资料或业务确认；完成判定只认数据状态。
- 新建空白货单不继承示例文件；案例通过「载入案例」单独提供。

## 验收流程（已实测通过）

100 箱 vs 120 箱不一致 → 客户确认 100 箱与新地址 → 货代按确认更新至 V3 → 复检一致 → 生成并下载 Excel 草稿 → 记录提交 → 回件仍为旧地址被标出 → 载入修正回件 → 本票资料流程完成。

`docs/` 为上一版（三轮试跑报告与优化建议）的存档。新版为单文件实现（index.html），数据保存在浏览器本地。
